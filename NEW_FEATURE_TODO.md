## 1. Смешанная раскладка для трёх satellite-окон

### Поведение

- [x] Добавить явно включаемый смешанный режим: при **ровно трёх satellite-окнах**, то есть четырёх окнах вместе с master, два satellite занимают верхние места рядом, третий — широкое нижнее место.
- [x] Существующие режимы Horizontal и Vertical сохранить. Старые настройки должны загружаться с прежним поведением; смешанный режим самовольно не включать.
- [x] Выбор смешанного режима доступен в настройках, сохраняется и применяется без перезапуска. Preview настроек показывает фактическую схему.
- [x] При числе satellite меньше трёх или больше трёх использовать существующую обычную раскладку. Выбор смешанного режима сохранять: при возвращении к трём satellite схема включается снова. `MaxSatellites` и overflow продолжают действовать независимо.

Под «горизонтальным окном» здесь понимается широкое нижнее место H, под «вертикальными» — два верхних места V1/V2. Это геометрия мест, а не постоянное свойство приложения и не название существующего enum `SatelliteLayoutOrientation`.

```text
Master справа                    Master слева
┌──────┬──────┬──────────┐       ┌──────────┬──────┬──────┐
│  V1  │  V2  │          │       │          │  V1  │  V2  │
│      │      │  MASTER  │       │  MASTER  │      │      │
├──────┴──────┤          │       │          ├──────┴──────┤
│     H      │          │       │          │     H      │
└─────────────┴──────────┘       └──────────┴─────────────┘
```

Практичные исходные решения для деталей, которые пользователь не задавал:

- Базовая схема — H снизу; отдельные варианты с полосой сверху/сбоку в этот этап не входят.
- Верхняя часть получает 2/3 высоты satellite-области, нижняя — 1/3; V1/V2 делят верхнюю ширину поровну до учёта отступов и ограничений размеров. Все размеры относительные, по `WorkArea` и существующим правилам `MinSize`.
- При первом входе в схему порядок satellite задаёт места V1, V2, H. Для дальнейших операций хранить/восстанавливать фактический порядок мест; фокус сам по себе его не меняет.
- После выхода из схемы сохранять относительный порядок оставшихся окон. Не добавлять отдельную историю расположения или настройки пропорций без необходимости.

### Обмен горизонтального и вертикального места

- [x] Направленные команды перемещают сфокусированное окно в соседнее место и **обменивают двух участников местами**. Для смешанной схемы не использовать вставку в список со сдвигом третьего окна.
- [x] H → вверх на V1: прежнее H становится V1, прежнее V1 становится H; V2 остаётся на месте. Аналогично для V2.
- [x] V1/V2 → вниз на H: выбранное вертикальное окно становится H, прежнее H занимает точное освобождённое верхнее место. Другое верхнее окно не меняется.
- [x] V1 → вправо на V2 и V2 → влево на V1 меняют верхние окна местами; H не меняется.
- [x] Добавить назначаемую в существующих keybindings команду переключения сфокусированного satellite между широким и верхним местом. Верхнее окно обменивается с H; H — с тем же верхним соседом, который выбирается для MoveUp. Не переопределять молча существующую команду переключения ориентации всей satellite-группы и не занимать конфликтующее сочетание клавиш.
- [x] Для H → вверх использовать существующий геометрический выбор соседа. Если V1/V2 равнозначны, выбрать V1 (верхнее левое место). Выбор должен быть детерминированным и одинаковым у проверки доступности команды и её выполнения.
- [x] При drag-and-drop на конкретное satellite-окно обменивать именно эти два места; preview и результат отпускания совпадают.
- [x] После обмена фокус остаётся на перемещаемом окне. Не менять master, его сторону, ratio или третье satellite-окно.
- [x] Вне смешанной схемы новая команда переключения места недоступна либо даёт штатный отказ без изменения layout.

Пример обмена: `[V1=A, V2=B, H=C]` → MoveDown(A) → `[V1=C, V2=B, H=A]`.
Обратное перемещение A в V1 возвращает исходную схему. Широкое место остаётся снизу: меняется окно, которое его занимает.

## 2. Направленные перемещения между master и satellite

### Обязательная зеркальная семантика

| Исходное состояние | Действие | Результат |
|---|---|---|
| Master справа, satellite слева | Satellite движется вправо, непосредственно сосед справа — master | Satellite становится master справа; прежний master занимает точное прежнее satellite-место слева |
| Master слева, satellite справа | Satellite движется влево, непосредственно сосед слева — master | Satellite становится master слева; прежний master занимает точное прежнее satellite-место справа |
| Master справа | Master движется влево | Тот же master становится слева; вся satellite-группа переходит вправо |
| Master слева | Master движется вправо | Тот же master становится справа; вся satellite-группа переходит влево |

- [x] Переход satellite → master работает в обычных Horizontal/Vertical и в новом смешанном режиме. Не ограничивать его текущей осью satellite-группы.
- [x] Определять **непосредственного геометрического соседа**. Если между выбранным satellite и master находится другой satellite, первый шаг перемещает/обменивает satellite внутри группы по правилам режима, без прыжка через окно к master.
- [x] В смешанной схеме при master справа V2 и H непосредственно соседствуют с master; V1 сначала обменивается с V2 при MoveRight. При master слева V1 и H соседствуют с master; V2 сначала обменивается с V1 при MoveLeft.
- [x] При promotion сторона master сохраняется. Старый master наследует **точное место** выбранного satellite, включая H/V1/V2 в смешанной схеме. Остальные satellite не сдвигаются.
- [x] При перемещении самого master на противоположную сторону он сохраняет роль master и фокус. Satellite сохраняют свои роли и внутренние места: смена стороны не разворачивает их порядок и не меняет верх/низ.
- [x] MoveLeft у уже левого master и MoveRight у уже правого master ничего не переставляют. Вертикальное движение master не превращает его в satellite. Сохранить согласованное существующее поведение отказа/no-op.
- [x] Движение satellite к внешнему краю без соседа не меняет роли и не оборачивается на другую сторону.
- [x] Ratio master, выбранный режим, состав окон и принадлежность desktop/display сохраняются. Перестановка внутри layout не запускает overflow и не переводит окно во floating.
- [x] Для клавиатуры использовать существующие MoveLeft/Right/Up/Down, включая direct hotkeys. Проверка `CanMove...` должна совпадать с фактическим результатом движения.
- [x] Для drag-and-drop сохранить ту же семантику ролей: satellite на место master — promotion; master на противоположную сторону — смена стороны с сохранением master. Отдельная явно вызванная команда promotion продолжает делать именно promotion.
